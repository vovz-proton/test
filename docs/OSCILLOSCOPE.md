# UNI-T UTD2102CL+: инструкция для следующего бота

Проверено 26.10.2026 на компьютере пользователя, Windows 11 Pro x64.
Это локальная инструкция для конкретного прибора, а не универсальный драйвер.
Подключение и чтение обоих каналов реально проверены. Старые измерения не являются текущими.

NI-VISA завершил установку с кодом 3010 (запрошена перезагрузка), но связь и чтение уже заработали без неё. Не перезагружай компьютер автоматически.

## Быстрый старт

Используй 64-разрядный PowerShell через инструмент выполнения команд. Для обычного чтения повышение прав не потребовалось. Не требуется открывать GUI Device Manager.

Проверенный скрипт находится в проекте:
`D:\YandexDisk\Programs\ST18\Prof_KIP_v5\tools\oscilloscope\query-scope.ps1`.
Исходный экземпляр и установочные файлы сохранены в
`C:\Users\vovz\Downloads\UNI-T-UTD2102CL`.

```powershell
Get-PnpDevice -InstanceId 'USB\VID_5656&PID_0832\1474742912' |
    Format-List Status, Class, FriendlyName

$scope = 'D:\YandexDisk\Programs\ST18\Prof_KIP_v5\tools\oscilloscope\query-scope.ps1'
& $scope -Query '*IDN?'
```

Успех запроса: `Status=0`, ненулевое `Bytes` и ожидаемый ответ прибора.
Скрипт использует P/Invoke к NI-VISA: `viOpenDefaultRM`, `viOpen`, `viSetAttribute`, `viWrite`, `viRead`, `viClose`. Таймаут — 3000 мс; команды заканчиваются LF. Сеанс закрывается в `finally`.

VISA считает ошибками отрицательные статусы. Положительный статус может означать предупреждение: например, при открытии Resource Manager наблюдался `1073676407`, после чего прибор успешно читался.

Адрес прибора в скрипте фиксированный. Если осциллограф заменён или адрес перестал находиться, перечисли ресурсы через `viFindRsrc` с выражением `USB?*INSTR`, проверь идентификацию и только затем меняй адрес. Не выбирай другое устройство наугад.

## Проверенные запросы

```powershell
& $scope -Query ':CHANnel1:SCALe?'
& $scope -Query ':CHANnel1:PROBe?'
& $scope -Query ':CHANnel2:PROBe?'
& $scope -Query ':CHANnel2:DISPlay?'
& $scope -Query ':TIMebase:SCALe?'
& $scope -Query ':MEASure:VPP? CHANnel1'
& $scope -Query ':MEASure:VAVerage? CHANnel1'
& $scope -Query ':MEASure:FREQuency? CHANnel1'
& $scope -Query ':MEASure:VPP? CHANnel2'
& $scope -Query ':MEASure:VAVerage? CHANnel2'
& $scope -Query ':MEASure:FREQuency? CHANnel2'
```

Используй `CHANnel1` / `CHANnel2`. Запрос частоты с аргументом `CH1` привёл к таймауту; полное имя работало.
Ответ `*` на запрос частоты означает отсутствие численного результата: не подменяй его нулевой частотой.
Автоматические измерения и отдельная выгрузка формы сигнала не синхронны, их размах может различаться.
Проверяй коэффициент щупа в приборе; он не доказывает положение физического переключателя на щупе.

## Чтение формы сигнала

Сначала прочитай текущий источник, формат и режим, чтобы восстановить их после работы:

```powershell
& $scope -Query ':WAVeform:SOURce?'
& $scope -Query ':WAVeform:FORMat?'
& $scope -Query ':WAVeform:MODE?'
```

Пример для CH1, с новой папкой для каждой записи:

```powershell
$capture = Join-Path $env:USERPROFILE ('Downloads\UNI-T-UTD2102CL\captures\' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $capture -Force | Out-Null
& $scope -Query ':WAVeform:SOURce CHANnel1'
& $scope -Query ':WAVeform:FORMat WORD'
& $scope -Query ':WAVeform:PREamble?' | Set-Content (Join-Path $capture 'ch1-preamble.txt')
& $scope -Query ':WAVeform:DATA?' -OutputFile (Join-Path $capture 'ch1-waveform.bin')
```

Для CH2 выбери `:WAVeform:SOURce CHANnel2`, сохрани его собственную преамбулу и бинарный файл. Затем восстанови исходные источник и формат. При нашей проверке исходными были `CHANnel1` и `WORD`, режим — `NORMal`.

Не меняй без необходимости развёртку, масштаб, запуск или физические настройки измерения. Для чтения, выполненного в этом чате, `AUTO`, `STOP`, сброс и калибровка не требовались. RAW-режим и чтение глубокой памяти здесь не проверены.

## Обязательно проверяй бинарные данные

Скрипт — минимальный помощник, а не готовая библиотека сбора данных:

- Один вызов `viRead`, буфер 1 МиБ. Многоблочное чтение не реализовано.
- При ошибке чтения статус печатается, но частичные данные могут быть сохранены. Наличие файла не означает успешную запись.
- `OutputFile` перезаписывается. Выбирай новые имена/папки.
- Вызов без `?` только отправляет команду. Передавай одну команду за вызов.

Ответ WORD содержит заголовок IEEE 488.2: `#`, цифра N, N цифр длины и затем данные. Проверяй, что фактически получена вся заявленная длина. Заголовок не является частью отсчётов.

Реально полученные файлы обоих каналов: 3211 байт, заголовок `#9000003200`, за ним 3200 байт — 1600 little-endian 16-битных слов. Старший байт слов в проверенной записи равен нулю.

Пример проверки и декодирования на Python, без дополнительных библиотек:

```python
from pathlib import Path
import struct

raw = Path(r'C:\path\to\ch1-waveform.bin').read_bytes()
assert raw[:1] == b'#'
n = int(raw[1:2])
assert 1 <= n <= 9
start = 2 + n
length = int(raw[2:start])
payload = raw[start:start + length]
assert len(payload) == length, 'Неполный блок'
assert length % 2 == 0
codes = struct.unpack('<' + 'H' * (length // 2), payload)
```

Преамбула возвращает поля:
`Format,Type,Points,Count,Xinc,Xor,Xref,Yinc,Yor,Yref`.
В этой прошивке первые поля строковые (`WORD,NORMal`), хотя руководство также описывает числовые значения.

**Неразрешённое расхождение:** преамбула сообщала `Points=800`, а WORD-блок содержал 1600 слов. Не утверждай, что это 1600 независимых временных точек, и не вычисляй частоту по этой записи без проверки формата. Не угадывай, являются ли значения парами min/max. Предыдущий график использует только индекс возвращённого слова.

При `Yor=0`, как в нашей записи, напряжение вычислялось как `(code - Yref) * Yinc`; это согласовалось с началом ASCII-ответа. Пересчёт при ненулевом смещении дополнительно не проверен.

ASCII-режим оказался непригоден с этим минимальным скриптом: заголовок объявил 22399 байт, но один `viRead` вернул всего 3211 байт вместе с заголовком. Статус при этом был 0. Файл `ch1-ascii-INCOMPLETE.txt` является неполной пробой, не используй его как полную осциллограмму.

## Если связь не работает

1. Проверь наличие устройства и статус PnP. До установки оно называлось `dso-2e` и имело код 28; после установки — `USB Test and Measurement Device (IVI)`.
2. Проверь наличие `visa64.dll` и 64-разрядность процесса. Не начинай сразу с переустановки.
3. Проверь адрес VISA и `*IDN?`. Исключи одновременное чтение другим ботом или GUI.
4. Таймаут `-1073807339` может означать неподдерживаемый синтаксис запроса, а не обрыв USB. Сверь полные имена команд.
5. Если нужен новый драйвер, не устанавливай CH341SER/CH375 для этого устройства: их аппаратные ID не совпадают с `5656:0832`.
6. Установка системных компонентов требует прав администратора; обычное чтение уже работало без них. UAC может потребовать действия пользователя. Не обещай автоматическое подтверждение.

## История установки — только для восстановления

Основная папка: `C:\Users\vovz\Downloads\UNI-T-UTD2102CL`.
Архив `UTD2000CL-Software.zip` скачан по ссылке Software на официальной странице прибора; внутри `Package\Device Manager Installer.exe`.

Первоначальный EXE выдавал `Server returned unexpected error 3`. Прямой запуск MSI сначала отказался работать без bootstrapper. Рабочий путь:

1. Штатная распаковка Advanced Installer: `Device Manager Installer.exe /extract "существующая_папка" /exenoui` с повышением прав.
2. В `Extracted\143B4C0` появились MSI и файлы программы. Установка этого MSI с `SETUPEXEDIR`, указывающим на папку исходного EXE, завершилась с кодом 0. Использовались `/qn /norestart /L*V` и обычные Windows-пути с обратными слешами.
3. Отдельно запущен `Extracted\setup.exe` — NI-VISA — с параметрами `/q /acceptlicenses yes /r:n`, повышением прав и рабочим каталогом `Extracted`. Итог 3010; USB-драйвер заработал.

Это описание уже выполненного ремонта, не инструкция переустанавливать ПО при каждом обращении. Не запускай несколько установщиков одновременно. Не используй оставшийся `install-visa.ps1`: тот промежуточный способ не подтвердил выполнение; успешная установка выполнена отдельным запуском EXE.

Журналы: `install-extracted.log`, `bootstrap.log`, `bootstrap-msi.log` в папке загрузок; NI — `C:\ProgramData\National Instruments\Installation Logs`.

## Проверенное управление вертикальным масштабом (26.10.2026)

Перед `:CHANnel<n>:SCALe <value>V` обязательно отправляй `:CHANnel<n>:SELect`.
На прошивке 1.07.0064 без SELect команда SCALe меняла выбранный на передней панели
канал, даже когда в команде был явно указан другой номер. Проверено на обоих
каналах: после SELect меняется нужный канал, соседний остаётся неизменным.
Результат подтверждай запросом `:CHANnel<n>:SCALe?`.
